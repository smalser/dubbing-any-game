# Архитектура и расширение

```text
dub.py                    # переносимая точка входа
dubbing/cli.py            # аргументы, конфигурация, запуск этапов
dubbing/manifest.py       # схема, выборка и исключения
dubbing/storage.py        # строгий JSON, хэши, атомарная запись, locks
dubbing/synthesis.py      # идентичность модели, batch cache и синтез
dubbing/processing.py     # FFmpeg fit, peak cap и verification
dubbing/audio.py          # общая валидация WAV
dubbing/adapters/tts.py    # Qwen, mock и подключаемые классы
dubbing/platforms/        # особенности ОС и обнаружение инструментов
dubbing/integrations/     # контракты и будущие интеграции игровых форматов
tools/                    # подготовка окружения
examples/                 # demo и локальная страница сравнения
work/                     # приватные задания и результаты
```

## Границы модулей

Ядро оперирует репликами и WAV. Оно не знает расположения установленной игры, формата банков или команды сборки игровых архивов. Модули ОС отвечают за различия путей, исполняемых файлов и диагностики. Интеграция игры отвечает за извлечение, доказанное сопоставление, формат контейнера, упаковку и установку.

Публичный контракт интеграции — проверенный манифест на входе и проверенное аудио с метаданными на выходе. Начать новую игру можно без правок ядра: подготовить манифест и отдельный сборщик. Включение нового движка не должно добавлять его зависимости в минимальную установку.

## Данные

Реплике нужны стабильный ID, текст, говорящий, сюжетная секция/порядок, локальный оригинал и целевой формат. Для клонирования голоса нужен отдельный референс говорящего. Сохраняйте sample rate, каналы, число кадров, источник текста и игровые внутренние пути в метаданных интеграции. Реальные имена JSON-полей задают валидатор и `examples/demo/manifest.json`.

Минимальная структура текущей схемы (число кадров и формат берите из реального аудио):

```json
{
  "schema_version": 1,
  "lines": [
    {
      "id": "line_001",
      "speaker": "speaker_01",
      "text": "Пора идти.",
      "reference": "audio/speaker_01.wav",
      "original": "audio/line_001.wav",
      "scene": "chapter_01/scene_01",
      "status": "ready",
      "format": {"sample_rate": 24000, "channels": 1, "frames": 48000}
    }
  ]
}
```

Порядок массива `lines` сохраняется. Синтез допускает `ready` и `reviewed` (отсутствующий status означает ready). Исключённые статусы: `unknown`, `blocked`, `excluded`, `silence`, `nonverbal`, `development`; для них обязателен непустой `reason`. Неизвестный status считается ошибкой. `reference` обязателен даже для mock. `original` нужен для сопоставления громкости; без него выбирайте `--loudness none`. Поля интеграции можно хранить дополнительно; ядро их не интерпретирует.

Ветки сюжета и неоднозначные связи храните явно. Пути reference/original разрешаются относительно манифеста; абсолютные пути и `..` допустимы для собственных внешних каталогов. Манифест — доверенный локальный документ, не sandbox: не запускайте непроверенный чужой config. Входы не могут находиться среди генерируемых raw/fitted/batches или совпадать со служебными файлами output. ID ограничены ASCII, проверяются без учёта регистра и не могут быть Windows device names. Структура проверяется у всех строк, наличие файлов — у выбранной очереди.

## Адаптер TTS

`mock` позволяет проверить инфраструктуру без нейросети. `qwen` реализует локальный синтез. Для другой модели добавьте адаптер по тому же Python-контракту или загрузите внешний класс предусмотренным механизмом. Формального базового класса нет: контракт задают методы существующих адаптеров в `dubbing/adapters/tts.py`.

Контракт — `load(config)` и `synthesize(rows, config)`. В rows передаются только `id`, `text`, `speaker`, `reference`; путь reference абсолютный. Результат — list/tuple из пар `(samples, sample_rate)` в порядке входа. Samples: числовой массив `[frames]` или `[frames, channels]`, 1–8 каналов, нормализованные конечные амплитуды строго внутри (-1, 1), непустой сигнал с ненулевой амплитудой. Sample rate — положительное целое (bool/float запрещены). Raw сохраняется PCM16; это нетронутый тайминг/уровень синтеза после необходимой записи в WAV, а не исходный float tensor модели.

Пример выбора: `--adapter my_package.adapter:MyAdapter`. Для fit/verify/package повторяйте те же настройки синтеза и выборку: размер и состав batch участвуют в кэше. Адаптер должен сбрасывать состояние RNG на каждом вызове из config.seed; результат группы не должен зависеть от того, сколько предыдущих групп было пропущено при resume. Qwen сбрасывает Torch/NumPy RNG перед каждым batch. Побитовая воспроизводимость на другом устройстве не обещается.

Адаптер отвечает за поддержку своих настроек и не выполняет fit или игровую упаковку. Модель идентифицируется хэшами локальных файлов (служебный `.cache` исключён); для внешнего класса учитывается файл его модуля. Автоматически хэшировать все импортированные зависимости внешнего адаптера ядро не умеет. Фиксируйте их версии и revision в `adapter_options`, которые входят в ключ, и обновляйте при смене реализации. Не скрывайте платный сервис за интерфейсом локальной модели. Загрузка внешнего класса исполняет Python-код: используйте доверенные пакеты.

## Воспроизводимость

Ключ группы учитывает IDs/тексты/говорящих/референсы всех её участников, модель, адаптер, настройки и версии зависимостей. Наличие WAV недостаточно: проверяются его хэш, метаданные и отдельная квитанция batch. Перед заменой файлов старая квитанция удаляется, новая записывается последней. При прерывании посреди commit весь batch считается незавершённым и повторяется. Это защита от process interruption, а не гарантия транзакционности при отказе накопителя.

Raw и метаданные сохраняются отдельно от fit. Код обработки не входит в ключ синтеза; его правка не требует TTS. Ключ fit включает raw, формат, выбранный original, параметры, реализацию обработки, версии NumPy/SoundFile, SHA256 FFmpeg executable и результат `ffmpeg -version`. Версия нужна в том числе для PATH launcher/shim. Динамические библиотеки с той же строкой сборки по отдельности не хэшируются.

Формат batch cache 0.2.0 несовместим с первоначальной схемой. Старые WAV не удаляются, но новый generate может заменить их после повторного синтеза. Сохраните прежний output для прослушивания и используйте новый каталог; автоматического доверенного мигратора нет.

Обработка и упаковка должны сверять полный выбранный набор IDs. Итоговые receipt и SHA256 позволяют отличить проверенный результат от промежуточного. Точность кадров — свойство технической совместимости, а не гарантия качества речи.
