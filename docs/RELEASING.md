# Подготовка к распространению

Эта инструкция готовит локальный кандидат. Публикация в GitHub, хостинг примеров и загрузка мода выполняются только по отдельному запросу владельца проекта.

Посмотреть состав исходного релиза: `python tools/source_release.py --dry-run`. Сборщик использует allowlist кода и документации и исключает media, models и work. Это ZIP исходников; `dub.py package` создаёт отдельный экспорт аудио. В чистом source ZIP demo WAV создаются командой `python tools/make_demo.py`.

1. Проверьте лицензию собственного кода, зависимостей, весов и голосовых материалов. Название модели и право скачать веса не равны праву распространять их или производные записи.
2. Проверьте состав Git и архива. Исключите модели, окружения, кэши, извлечённые игровые assets, оригинальные голоса, игровые бинарники, ключи и личные пути. Проверяйте уже отслеживаемые файлы: `.gitignore` не удаляет их из истории.
3. Отдельно проверьте examples/comparison. Реальные аудио могут оставаться локально; публичная страница должна работать с разрешёнными материалами или ясно объяснять отсутствие аудио. Не коммитьте оригинал только ради работающего плеера.
4. Выполните тесты и smoke-тест из чистого окружения. Запишите реально проверенные ОС, Python, FFmpeg, адаптер, модель и устройство. Для Linux/macOS и Qwen не переносите результат Windows mock-теста автоматически.
5. Для релиза аудио сохраните точное покрытие IDs, исключения, manifest, настройки и SHA256. Технические проверки, прослушивание и in-game QA перечисляйте отдельно.
6. Для игрового мода добавьте версию игры, способ установки, конфликтующие моды, backup и откат. Переносимый WAV ZIP сам по себе не является готовым модом.

До публичного выпуска нужны независимый тест второй игры, проверка документации новым пользователем и матрица поддержанных моделей/платформ. Не объявляйте универсальность проверенной только на основании интерфейса адаптеров.
