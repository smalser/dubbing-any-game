# Плейбук: от собственной игры до озвучки

Это рабочий маршрут для человека и агента. Начните с [быстрого старта](../README.md#быстрый-старт) или [установки Skill](SKILL.md). Требования к поведению агента — в [AGENTS.md](../AGENTS.md), установка — в [SETUP.md](SETUP.md), параметры команд — в [CLI.md](CLI.md).

## Как выбрать следующий шаг

| Что уже есть | С чего продолжить | Условие перехода дальше |
|---|---|---|
| Только репозиторий | 1. Подготовка | Doctor и mock-конвейер проходят |
| Игра, но нет доказанного манифеста | 2–3. Исследование и данные | Сохранены mapping, исключения и целевые форматы |
| Проверенный манифест и референсы | 4. Короткий синтез | Несколько реплик прослушаны и приняты |
| Сохранённые raw WAV | 5. Обработка | Verify проходит, речь проверена на слух |
| Проверенные WAV | 6. Игровая интеграция | Проверены сцена, состав мода и откат |
| Проверенный мод для распространения | 7. Выпуск | Проверены права и состав поставки |

Продолжая существующую работу, сначала прочитайте config, `status.json` и `events.jsonl` её output. Правила возобновления и проверки locks приведены в [CLI.md](CLI.md#остановка-восстановление-и-кэш). Изменение громкости или тайминга начинайте с `fit` сохранённых raw.

## 1. Подготовить рабочее место

Скопируйте репозиторий в отдельную папку и откройте её в Codex или Claude. Агент читает AGENTS.md, создаёт локальное окружение по SETUP.md, показывает состав зависимостей и проверяет doctor. Установка репозитория в агент не заменяет установку Python, FFmpeg, драйверов и модели.

Основной путь — локальный Qwen3-TTS; другую модель подключайте через адаптер по выбору пользователя. Для диагностики окружения выполните [mock-тест](SETUP.md#проверка-установки-с-mock), затем проверьте 2–4 короткие реплики с настоящей моделью. Не начинайте всю очередь до прослушивания результата.

В чистом исходном ZIP сначала выполните `python tools/make_demo.py`. Для demo используйте `--config examples/demo/config.json` на всех этапах. Для своей задачи сохраните отдельный config и переопределяйте нужные параметры CLI-флагами.

## 2. Исследовать игру

Профиль `game` обязателен для этого и последующих игровых этапов:

```text
python -m pip install -e ".[game]"
python dub.py doctor --config examples/demo/config.json --game-tools
python -m um --version
python -m um scan "/path/to/game" --json
```

Universal Modder закреплён на проверенном commit в `pyproject.toml`. Команда `python -m um` использует окружение проекта и не зависит от активации console script в PATH. [Требования](REQUIREMENTS.md) отдельно перечисляют инструменты конкретной интеграции. Само наличие Universal Modder ещё не подтверждает соответствие игровых текстов и аудио: сохраните результаты исследования и докажите цепочку IDs.

Установите и примените [Universal Modder](https://github.com/rehan-remade/universal-modder) по его актуальной инструкции. Попросите агента определить движок, версию, форматы текста и звука, способ загрузки мода, ограничения платформы и маршрут восстановления. Возможность моддинга зависит от игры; неподдерживаемый формат может требовать отдельной разработки.

Пример задачи агенту:

> Используй Universal Modder для моей локальной игры. Подготовь инвентарь реплик, докажи связь текста и говорящего, опиши извлечение и обратную упаковку. Сначала сделай одну проверяемую замену в отдельном моде. Не меняй оригинальные архивы и сохранения.

## 3. Подготовить манифест

Перед этим этапом заполните [контрольные результаты исследования](INTEGRATION_GATE.md): coverage CSV, точное доказательство ID mapping, unresolved list и проверяемый маршрут одной обратимой замены. Если этих доказательств нет, следующий шаг — конкретный эксперимент с игровым форматом; команда generate не может восполнить неизвестные данные. [Пилот Rue Valley](RUE_VALLEY.md) показывает отдельную интеграцию с Articy и FMOD; его команды и ограничения относятся к проверенной версии игры.

Интеграция извлекает оригинальное аудио и текст локально, связывает их по доказанным IDs, назначает говорящего и сохраняет целевой формат. Требования к данным приведены в [ARCHITECTURE.md](ARCHITECTURE.md); точную схему сверяйте с демонстрационным JSON и валидатором текущей версии.

Храните отдельно готовые строки, неизвестных говорящих, конфликты текста, тишину, невербальные звуки и тестовые assets. Не выдавайте доступную выбранную очередь за все звуковые assets игры. Ветвящийся сюжет не имеет гарантированного единственного линейного порядка.

## 4. Настроить голоса и синтез

Для Qwen выполните [установку модели и отдельный речевой тест](QWEN.md). Это проверка окружения, не замена игрового пилота.

Используйте разрешённые референсы и запишите источник каждого голоса. Установите адаптер и веса модели локально. Выберите модель, язык, устройство, тип вычислений и размер batch. Сравните короткую пробу с оригиналом, включая произношение, тембр и характер речи.

Сохраните seed и настройки. Одинаковый seed не гарантирует побитовое равенство при другой модели, оборудовании, версии библиотек или форме batch. Меняйте по одному параметру и сохраняйте raw WAV.

## 5. Обработать и проверить

Выполните doctor → plan → generate --dry-run → generate → fit → verify → preview с одним config и одной выборкой. Режим speedup ускоряет длинную запись и дополняет короткую тишиной; замедления по умолчанию нет. Если требуется чрезмерное ускорение, отредактируйте текст или повторите синтез с отдельным output. Не обрезайте смысл ради точного тайминга.

Проверьте ожидаемые IDs, непустой конечный сигнал, исходный формат и целевую длину, громкость и клиппинг. Прослушайте образцы разных персонажей, короткие реплики и максимальные ускорения. При необходимости добавьте ASR как фильтр грубых ошибок; он не заменяет слуховую проверку.

## 6. Собрать мод и проверить в игре

`package` сохраняет переносимый ZIP проверенного аудио. Игровая интеграция отдельно кодирует нужный формат, декодирует его обратно для сверки и собирает точный список внутренних путей. Частичный мод должен явно перечислять заменённые IDs и сохранять остальное оригинальным.

Устанавливайте собственный мод при закрытой игре, с уникальным backup и контрольными суммами. Проверьте сцену в игре, громкость относительно музыки и эффектов, запуск событий и откат. Не объявляйте in-game QA выполненным до реального запуска.

## 7. Подготовить распространение

Сохраните покрытие, исключения, версии, настройки, хэши, инструкцию установки и отката. Пройдите [RELEASING.md](RELEASING.md). Публичный код, модель и мод могут иметь разные лицензии и условия; проверяйте их отдельно.

## Что передать по окончании работы

Укажите использованный config, выбранные IDs, каталог результатов и выполненные команды. Отдельно перечислите технически проверенное, прослушанное и проверенное в игре. Запишите фактические ОС, модель, устройство, ограничения и следующий шаг; для установки — путь backup и способ отката. Не объявляйте пилот полной озвучкой.
