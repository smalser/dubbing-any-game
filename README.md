# Universal Dubbing

**Хотите сделать озвучку игры на своём языке?** Universal Dubbing помогает превратить подготовленные тексты в речь и подготовить аудио для игрового мода. По умолчанию для речи используется **Qwen3-TTS**, локально на вашем компьютере. Другую модель можно подключить через адаптер.

Первый результат, к которому стоит идти, — **2–4 озвученные реплики, которые вы услышали в самой игре**. После этого можно расширять очередь. Для каждой новой игры сначала нужно разобраться, где хранятся диалоги и как подключить замену звука; готового способа для любой игры здесь пока нет.

## Быстрый старт

### 1. Скачайте проект

На GitHub выберите **Code → Download ZIP**, распакуйте архив и откройте папку в своём ИИ-агенте с доступом к локальным файлам и терминалу. Или клонируйте:

```text
git clone --branch main https://github.com/smalser/dubbing-any-game.git
cd dubbing-any-game
```

Эта папка — рабочая копия приложения. Все команды выполняются из неё, рядом с `dub.py`.

### 2. Установите Skill для агента

В Codex отправьте:

```text
Используй skill-installer и установи skill universal-dubbing из
https://github.com/smalser/dubbing-any-game/tree/main/skills/universal-dubbing
```

Skill содержит рабочие инструкции: исследование игры, настройку модели, подготовку реплик, проверки и интеграцию. Он не устанавливает само приложение или веса. [Подробная установка и обновление Skill](docs/SKILL.md) описывает ручное копирование и вариант для агента без поддержки навыков.

### 3. Установите Qwen

Пройдите [пошаговый гайд Qwen](docs/QWEN.md): окружение → PyTorch → пакет Qwen → загрузка весов → запись голоса → первая произнесённая фраза. Это можно поручить установленному Skill.

По умолчанию используем **Qwen3-TTS-12Hz-1.7B-Base**. Веса занимают около 4,54 GB для revision из гайда; пакеты и результаты требуют дополнительного места. Синтез локальный, веса загружаются отдельно. Для клонирования нужен разрешённый образец голоса: для первой проверки можно записать свой. [Другую модель](#если-нужна-другая-модель) можно подключить через адаптер.

### 4. Дайте агенту задачу на свою игру

Со следующего сообщения после установки Skill отправьте запрос, заменив поля в квадратных скобках:

```text
Используй $universal-dubbing.
Рабочая копия Universal Dubbing открыта в текущей папке.
Хочу озвучить [название игры] на [язык].
Игра установлена в [путь к папке игры].
Перевод диалогов: [есть в игре / есть отдельный файл / пока нет].
Используй локальный Qwen; проверь моё оборудование и окружение.
Сначала подготовь 2–4 реплики одной сцены и дай мне прослушать.
До скачивания весов сообщи размер и получи разрешение.
Установку мода и запуск игры согласуй со мной.
```

**Перевод текста и озвучка — разные этапы.** При наличии нужных субтитров агент проверит их соответствие репликам; иначе сначала подготовит текст пилота. Встроенной команды перевода нет: `--language` задаёт язык произношения. Перевод меню и интерфейса требует отдельной работы.

Вам не нужно вручную угадывать формат JSON. Агент подготовит **манифест** — список текстов, говорящих, образцов голоса и длительностей — и **config** с настройками. Неизвестные соответствия он должен исследовать или явно исключить.

### 5. Проверьте результат

| Что вы получили | Что это подтверждает |
|---|---|
| WAV и `listen.html` | Можно прослушать речь и оценить текст, голос и темп |
| `verification.json` | Аудио прошло технические проверки |
| Отдельный мод с установкой и откатом | Подготовлен способ подключить звук к этой игре |
| Проверенная сцена в игре | Нужные реплики действительно звучат в нужный момент |

`package` создаёт архив WAV. Чтобы услышать их в игре, нужен отдельный способ замены звука. Он зависит от игры и может потребовать разработки. После успешного пилота расширяйте очередь; если интеграция заблокирована, агент должен назвать конкретную причину и следующий эксперимент.

## Если нужна другая модель

**Qwen — встроенный вариант по умолчанию, но ядро не привязано к одной модели.** Адаптер — Python-класс, который загружает модель и возвращает аудио для списка реплик.

| Выбор | Что настроить |
|---|---|
| Qwen3-TTS | `adapter: qwen`, локальные совместимые веса в `model`, профиль `.[qwen]` |
| Другая модель | Установить или написать адаптер, указать `adapter: my_package.adapter:MyAdapter` и его настройки |
| Диагностика WAV | `adapter: mock`; создаёт тон и не используется для озвучки |

`my_package.adapter:MyAdapter` — пример имени класса, не готовый установленный адаптер. Простая замена пути `model` не превращает Qwen-адаптер в поддержку другой архитектуры. Контракт `load(config)` и `synthesize(rows, config)` описан в [ARCHITECTURE.md](docs/ARCHITECTURE.md#адаптер-tts).

Для новой модели отдельно проверь зависимости, язык, поддержку голосовых референсов и устройство, затем выполни короткий реальный синтез. Doctor не выполняет полный preflight внешнего адаптера. Сохраняй эксперименты с разными моделями в разных output; последующие этапы обработки и экспорта остаются общими.

## Текущий статус

Версия **0.3.0**. В журнале проверок зафиксированы 66 тестов на Windows x64 и ограниченный пилот Rue Valley: четыре естественных игровых события одного NPC. Для Qwen3-TTS-12Hz-1.7B-Base проверен локальный preview на CUDA / bfloat16 / SDPA. Это не подтверждение массовой озвучки или поддержки всех устройств. Linux/macOS и шаблон CI пока не проверены; полная слуховая оценка пилота остаётся открытой. Подробности и исторические прогоны — в [VALIDATION.md](docs/VALIDATION.md).

[Страница сравнения](examples/comparison/index.html) предназначена для локального просмотра; её аудио может отсутствовать в публичной копии. Модели, игровые материалы, голосовые референсы и рабочие результаты не входят в исходный релиз. Перед распространением аудио или мода выполните [проверку прав и состава](docs/RELEASING.md).
