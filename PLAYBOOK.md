# Локальная нейроозвучка: рабочий плейбук

Цель — воспроизводимый путь от одной реплики до расширяемой очереди. Универсален процесс; формат игровых данных и сборки реализуется адаптером конкретной игры.

## 1. Исходная среда

**Вход:** собственная установленная игра, желаемый язык, оборудование. Зафиксировать магазин/build, движок, формат архивов, аудиосистему, пути saves/config. Сохранить резервную копию saves/config до первого тестового запуска.

**Выход:** журнал с версией и выбранным способом модификации. **Проверка:** перечислить и извлечь один asset без изменения архивов. Если стандартный инструмент не поддерживает контейнер, сначала исследовать формат; не обходить DRM/античит.

## 2. Manifest — источник истины

Для каждого ID нужны text EN/RU, speaker identity, source bank/media, WAV/XML, исходные frames/rate/channels, chapter/scene/order, status/blockers/evidence. Пример схемы — `examples/manifest.json`.

Сначала разрешить связь «реплика → персонаж → событие → медиа». Не назначать персонажа по похожему голосу или ближайшему произвольному идентификатору. Не считать одинаковый короткий текст достаточным доказательством соответствия. Учитывать локализованные пробелы, punctuation aliases, shared media и альтернативные пути к одному ID.

**Выход:** ready и blocked очереди, coverage report. **Проверка:** уникальные ID, разрешённые пути внутри корня, отсутствие конфликтов media, история ручных overrides. **Отказ:** сомнительные строки остаются blocked; никаких догадок для заполнения процента.

## 3. Одна реплика через весь путь

Декодировать оригинал, сгенерировать короткий тест, обработать, преобразовать в нужный codec, собрать override и проверить в игре. Сохранить bank/media ID, параметры и hashes. Только после реального подтверждения расширять сцену. Не восстанавливать saves автоматически ради повторного теста.

## 4. Голоса и baseline

Референс должен принадлежать установленному персонажу, без второго говорящего; акустическое качество прослушивается отдельно. Сначала сравнить 2–3 реплики на целевом языке. В исследованном случае пользователь предпочёл Qwen3-TTS 1.7B, Russian, speaker embedding only, без английского transcript conditioning.

Сохранить исходный референс локально, его SHA256, модель и настройки. Не публиковать голосовые образцы/embeddings вместе с инструкцией. Не обещать, что speaker embedding воспроизводит оригинальную интонацию каждой конкретной фразы.

## 5. Синтез, очередь и resume

Один GPU worker; игровую нагрузку освободить. Генерировать соседние по manifest записи пакетами. Сохранять WAV атомарно, затем metadata с текстом, speaker, fingerprint и hash WAV. При возобновлении проверять всё это; повреждённый или устаревший raw пересоздать.

Журнал JSONL хранит batch durations и IDs. Status содержит этап, текущую сцену, готово/всего, elapsed и приблизительный ETA. Оценка по числу реплик неточна при разной длине текста; уточнять её по фактическим партиям и отдельно учитывать CPU processing/QA/package.

**Остановка:** STOP-файл проверяется между партиями; lock защищает от параллельного запуска. После аварии проверять конкретный PID перед удалением stale lock. Никогда не убивать процессы по широкому шаблону.

**Проверка:** raw конечный, непустой, metadata совпадает; подозрение на token-limit truncation помечается. Прослушать новые голоса и сложные фразы. Текстовый ASR — дополнительный фильтр; команда общей ASR-проверки пока отдельная будущая задача.

## 6. Длительность и громкость

Хранить raw неизменным. Обрезать только внешнюю тишину; внутренние паузы сохранять. Записывать trim bounds.

```python
ratio = speech_seconds / original_seconds
tempo = max(1.0, ratio)  # стандартный режим
# tempo > 1: Rubber Band, pitch=1, formants preserved
# tempo == 1: не вызывать time stretching
# Затем padding до точного исходного числа кадров.
```

Режимы: `speedup` (default), `both` (экспериментальный), `pad` (не укорачивает длинную речь, выдаёт ошибку), `none` (переменная длительность, возможен рассинхрон).

Громкость: `original` сопоставляет full-file RMS с оригиналом, `lufs` делает двухпроходный loudnorm, `none` не нормализует. Отдельно задаются gain dB и peak cap. RMS зависит от тишины. Очень короткая реплика может не дать конечного измерения LUFS: реализация явно записывает fallback. Последующее усиление и ограничение пика могут изменить достигнутый LUFS.

**Проверка:** конечность, peak, формат, точные кадры в совместимом режиме, tempo>=1 для speedup. Слишком сильное ускорение — повод адаптировать перевод/пересинтезировать, а не считать исходный тайминг достаточным признаком качества.

## 7. Преобразование и упаковка

Адаптер обязан понимать codec и структуру bank. Проверять ожидаемые старые значения перед каждым patch; offsets получать из конкретного исходника. Сложный bank/shared media не обрабатывать универсальной заменой всех совпавших байтов.

Каждый replacement декодировать назад и сравнивать PCM с fitted WAV. Создавать свежий staging только из выбранных готовых записей. Точный список путей PAK должен совпадать с ожидаемым. Сохранять coverage, размеры, SHA256, параметры и verified status.

**Частичная готовность:** включать только существующие валидные записи, явно перечисляя покрытие. Непокрытая речь остаётся оригинальной. Готовый WAV ещё не означает, что он прошёл perceptual QA.

## 8. Установка, откат, проверка игроком

Игра закрыта. Сохранить текущий собственный пакет в уникальный backup, проверить конфликты overrides, скопировать новый PAK через временное имя, сверить hash. Не менять оригинальные архивы. Автоматическое отключение допустимо лишь для известных собственных пакетов, полностью покрытых новой сборкой; неизвестные/частичные пересечения требуют отдельного решения.

**Откат:** вернуть конкретный backup по install manifest, отключить заменивший его собственный пакет. Saves без отдельного решения не трогать.

Игрок проверяет начала сцен, ветки, пропуски, акцент, голос, паузы, громкость и темп. Каждое замечание записывать с scene/ID. Успешный импорт контейнера не заменяет эту проверку.

## 9. Материал для будущего skill

Каждый этап выше уже имеет вход/выход, критерий успеха и отказ. В skill перенести общую процедуру; игровые offsets, имена assets и код упаковки оставить в адаптерах. Историю экспериментов хранить отдельно от актуальных defaults. Перед публикацией перечислить весь allowlist файлов и проверить отсутствие игровых данных, личных путей и секретов.
